# IT Set Desk — Team Edition (v3.4.0)

نظام تذاكر لفريق الـ IT، بيشتغل على سيرفر واحد والفريق كله بيستخدمه من المتصفح.

- بيانات مشتركة في قاعدة SQLite.
- تسجيل دخول لكل موظف بصلاحيات (مدير نظام / موظف دعم).
- تحديث لحظي بين كل الأجهزة.
- واجهة **عربي / English** بضغطة زرار، وكل مستخدم ليه لغته.
- بوابة (Portal) للموظفين يفتحوا منها طلباتهم ويتابعوها.
- SLA بساعات العمل والإجازات، وسجل تدقيق محمي من التلاعب.

**المكونات:** Node.js 22 بمكتباته المدمجة بس (`node:http` + `node:sqlite`). مفيش ولا npm package.

---

## 1) التشغيل
```bash
cd itset-servicedesk-team
docker compose up -d --build
```
**هات كود الإعداد من الـ logs:**
```bash
docker compose logs servicedesk | grep "SETUP CODE"
```
افتح `http://<IP-السيرفر>:8080`، وأول مرة هتظهر لك **شاشة الإعداد**:
1. اكتب **كود الإعداد** (Setup code) اللي طلع لك في الـ logs.
2. اكتب اسمك وبريدك وكلمة مرور (8 أحرف على الأقل). ده بيبقى حساب **مدير النظام**.
3. اختياري: علّم على "تحميل بيانات تجريبية" لو حابب تجرب النظام الأول.

> الكود بيتغيّر مع كل إعادة تشغيل لحد ما الإعداد يخلص، وبعدها شاشة الإعداد بتتقفل نهائياً. مفيش حد يقدر يعمل حساب الأدمن من غير ما يكون عنده صلاحية على السيرفر نفسه.
> لو عايز كود ثابت (مثلاً في سكريبت تنصيب)، حطه في `SETUP_TOKEN` في ملف `.env`.

## 2) إضافة الفريق
الإعدادات ← **فريق العمل والصلاحيات** ← "إضافة موظف":
- **الاسم والبريد:** البريد هو اسم الدخول.
- **الصلاحية:** موظف دعم أو مدير نظام.
- **كلمة المرور:** لو سبتها فاضية، الموظف بيتضاف من غير دخول. ينفع تتسند له تذاكر، بس مش هيقدر يفتح النظام.

لكل موظف تقدر من زرار "الصلاحية وكلمة المرور" تعمل الآتي:
- تغيّر الصلاحية.
- تعيد تعيين كلمة المرور، وده بيعمل له تسجيل خروج فوراً.
- تلغي الدخول نهائياً.

لو قفلت "نشط" لموظف، بيتعمل له تسجيل خروج فوراً.

كل موظف يقدر يغيّر كلمة مروره من زرار اسمه أعلى الشاشة.

### الصلاحيات
| الإجراء | موظف دعم | مدير نظام |
|---|:-:|:-:|
| إنشاء التذاكر وتعديلها والرد عليها وتغيير حالتها وإسنادها | ✅ | ✅ |
| سجل الوقت، قائمة المهام، ربط التذاكر، CSAT | ✅ | ✅ |
| إضافة وتعديل الأصول ومقالات قاعدة المعرفة | ✅ | ✅ |
| حذف التذاكر والأصول والمقالات | ❌ | ✅ |
| الموظفين والصلاحيات، الفرق، التصنيفات، الردود الجاهزة | ❌ | ✅ |
| سياسات SLA والإعدادات العامة | ❌ | ✅ |
| تصدير واستيراد JSON | ❌ | ✅ |

الصلاحيات دي متطبقة **على السيرفر نفسه**، مش مجرد إخفاء أزرار في الواجهة.

## 3) نقل بياناتك من النسخة الـ Offline
النسخة الـ Offline بقت مبنية من نفس كود نسخة الفريق (القسم 11)، فالبيانات بتنتقل بين الاتنين في الاتجاهين.
1. في النسخة الـ Offline: الإعدادات ← تصدير نسخة احتياطية JSON.
2. في نسخة الفريق، وانت داخل كمدير نظام: الإعدادات ← استيراد JSON ← اختار الملف.

اللي بيتنقل: التذاكر والأصول والمقالات والإعدادات.

الحسابات اللي ليها دخول بتفضل زي ما هي. الموظفين اللي جايين من الملف بيتضافوا من غير دخول، ومحتاج تديهم كلمة مرور.

مقدمو الطلبات بيتعملوا تلقائياً من بيانات التذاكر القديمة: كل بريد إلكتروني بيبقى شخص واحد بكل تذاكره.

## 4) النسخ الاحتياطي وسلة المحذوفات
البيانات كلها في Volume اسمه `itset-data`.

### النسخ الاحتياطي التلقائي
- **نسخة يومية تلقائية** من جوه السيرفر، من غير cron ولا Task Scheduler. التوقيت بيتظبط من `AUTO_BACKUP_HOURS`.
- **نسخة أمان قبل أي استيراد.** لو النسخة دي فشلت، الاستيراد بيتلغي ومحدش بيلمس البيانات.
- كل نسخة بيتعمل لها **integrity check** بعد ما تتكتب، ولو طلعت بايظة بتتمسح ومبتحلش محل نسخة سليمة.
- كل نوع (يدوي، تلقائي، قبل الاستيراد) بيحتفظ بآخر 14 نسخة لوحده، فالنسخ التلقائية مش بتمسح نسخك اليدوية.
- الأدمن يشوف قايمة النسخ ويعمل **"Backup الآن"** من: الإعدادات ← النسخ الاحتياطية.

**نسخة يدوية من سطر الأوامر** (آمنة والسيرفر شغال):
```bash
docker compose exec servicedesk node backup.js
```
النسخ بتتحفظ في `/data/backups/` جوه الـ Volume بالشكل ده: `servicedesk-<نوع>-YYYYMMDD-HHMMSSmmm.db`.

### سلة المحذوفات
حذف تذكرة أو أصل أو مقال **مش نهائي**. العنصر بيروح لـ **سلة المحذوفات** (للأدمن بس)، ومنها:
- **استرجاع:** التذكرة بترجع بكل ردودها وسجلها. لو التصنيف أو الموظف المسؤول اتحذف في الفترة دي، النظام بيصلّح المراجع تلقائياً، وبيسجل "استرجع التذكرة" في سجل النشاط.
- **حذف نهائي** لعنصر واحد، أو **تفريغ السلة** كلها.
- أي عنصر بيعدي عليه `TRASH_DAYS` يوم (الافتراضي 30) بيتمسح نهائياً لوحده.

### نسخ الـ Backups لجهاز تاني (مُوصى به)
النسخ اللي جوه نفس السيرفر مش هتحميك لو الهارد باظ. خد نسخة لمكان تاني بشكل دوري:

```bash
docker cp itset-servicedesk:/data/backups ./backups
```
وجدول الأمر ده يومياً على Linux بـ crontab، أو على Windows بـ Task Scheduler، لـ NAS أو share تاني.

**الاسترجاع من نسخة:**
```bash
docker compose stop
docker run --rm -v itset-servicedesk-team_itset-data:/data -v "$PWD/backups":/b alpine \
  sh -c "cp /b/servicedesk-auto-YYYYMMDD-HHMMSSmmm.db /data/servicedesk.db && rm -f /data/servicedesk.db-wal /data/servicedesk.db-shm"
docker compose start
```
اسم الـ Volume بيبدأ باسم الفولدر. لو مش متأكد منه، اعرفه بـ `docker volume ls`.

**لو القاعدة باظت** (مثلاً بعد انقطاع كهربا مفاجئ): السيرفر بيعمل integrity check كل ما يشتغل. لو لقى مشكلة، **بيرفض يشتغل** بدل ما يكتب على بيانات بايظة، وبيكتب في الـ logs رسالة `DATABASE PROBLEM` فيها خطوات الاسترجاع. ساعتها استرجع آخر نسخة بالطريقة اللي فوق.

## 5) المرفقات
من تاب **المرفقات** في أي تذكرة تقدر ترفع ملفات بـ 3 طرق:
- **لصق Screenshot مباشرة بـ `Ctrl+V`** وانت فاتح التذكرة. الملف بيتسمى تلقائياً بالتاريخ والوقت.
- **سحب الملفات وإفلاتها** على التذكرة.
- زرار **"اختار ملفات"**، وتقدر تختار أكتر من ملف مرة واحدة.

الصور بتظهر لها معاينة، وباقي الملفات بتتحمل. الحد الأقصى للملف `MAX_UPLOAD_MB` (الافتراضي 15 ميجا)، و50 مرفق للتذكرة. اللي رفع الملف أو الأدمن بس يقدروا يحذفوه.

**الأمان:**
- النظام بيحدد إن الملف صورة **من محتواه الفعلي**، مش من اسمه. يعني ملف HTML اسمه `photo.png` بيتعامل معاه كملف عادي ومش بيتعرض كصفحة.
- أي ملف مش صورة بيتحمل download بس، ومعاه `nosniff` و`CSP sandbox`. ده بيمنع إن ملف مرفوع يشغّل كود جوه النظام.
- **الملفات التشغيلية ممنوعة من الأساس:** exe, msi, bat, cmd, vbs, js, hta, lnk, iso... علشان الـ Help Desk ميبقاش وسيلة توزيع لملف ضار.
- مسارات الملفات بتتشال من الأسماء، والأسماء العربي بتفضل زي ما هي.

**التخزين والنسخ الاحتياطي:**
- الملفات متخزنة في `/data/attachments/` جوه نفس الـ Volume. الملف المتكرر بيتخزن مرة واحدة بس.
- كل Backup بيعمل hard-link للملفات الجديدة في `/data/backups/attachments/`، فمفيش مساحة إضافية، والنسخة بتفضل موجودة حتى لو المرفق اتحذف.
- **الاسترجاع تلقائي:** لما تسترجع نسخة قاعدة قديمة وتشغّل السيرفر، المرفقات الناقصة بترجع لوحدها من الـ backup store. لاحظ إن **تصدير JSON بيحتوي على بيانات المرفقات بس، مش الملفات نفسها.**

## 6) الإشعارات
### داخل النظام (شغالة على طول)
الجرس 🔔 فوق بيعرض عدد الإشعارات اللي ماتقريتش، وعنوان التاب كمان بيعرض العدد. لما تضغط على إشعار، بيفتح التذكرة مباشرة.

| الحدث | مين بيتبلغ | بالإيميل؟ |
|---|---|:-:|
| تذكرة اتسندت لك (يدوي أو تلقائي) | المسؤول | ✅ |
| رد من مقدم الطلب على تذكرتك | المسؤول | ✅ |
| زميل رد أو أرفق ملف على تذكرتك | المسؤول | ❌ |
| التذكرة قربت تخرق الـ SLA (فاضل أقل من 25% من الوقت) | المسؤول، ولو مفيش مسؤول يبقى الأدمن | ❌ |
| التذكرة **خرقت** الـ SLA | المسؤول **والأدمن** (تصعيد) | ✅ |
| تذكرة P1 أو P2 اتفتحت ومحدش مسؤول عنها | الأدمن | ✅ |

- محدش بيتبلغ بحاجة هو اللي عملها.
- كل حالة SLA بيتبلغ عنها مرة واحدة بس، حتى بعد restart.
- الإشعارات بتوصل للموظفين اللي ليهم دخول على النظام بس، وبتتمسح بعد 60 يوم.

### إشعارات سطح المكتب
من **حسابي ← الإشعارات**: بيظهر إشعار من الويندوز أو الماك لما تاب النظام يكون في الخلفية.
> المتصفحات بتسمح بالنوع ده **على HTTPS بس**. يعني بيشتغل لو داخل من رابط Cloudflare (القسم 8)، ومش هيشتغل على `http://IP:8080` الداخلي. وده قيد من المتصفح نفسه، مش من النظام.

### الإيميل (اختياري)
حط إعدادات SMTP في `.env`، وبعدين من **الإعدادات ← الإيميل** اضغط **"إرسال إيميل تجريبي لنفسي"** علشان تتأكد. لو الإرسال فشل، الزرار بيعرض لك رسالة الخطأ اللي جاية من سيرفر الإيميل. وأي موظف يقدر يقفل الإيميلات عن نفسه من "حسابي".

```bash
APP_URL=https://helpdesk.company.com        # علشان الإيميل يبقى فيه رابط التذكرة
SMTP_FROM=IT Help Desk <helpdesk@company.com>
```

| مزوّد الإيميل | الإعدادات |
|---|---|
| **Microsoft 365** | استخدم **SMTP relay عن طريق Connector** (مصادقة بالـ IP، من غير باسورد): `SMTP_HOST=<domain>.mail.protection.outlook.com`، `SMTP_PORT=25`، `SMTP_SECURE=starttls`، وسيب `SMTP_USER` فاضي. واعمل في Exchange admin center ← Connectors ← connector من "Your organization's email server" بالـ IP العام بتاعك. |
| **Google Workspace / Gmail** | `SMTP_HOST=smtp.gmail.com`، `SMTP_PORT=587`، `SMTP_SECURE=starttls`، و`SMTP_USER` / `SMTP_PASS` يكون App Password (محتاج 2-Step Verification). |
| **سيرفر داخلي** (Exchange on-prem / Postfix) | `SMTP_HOST=<IP>`، `SMTP_PORT=25`، و`SMTP_SECURE=starttls` أو `none`. لو الشهادة self-signed: `SMTP_TLS_INSECURE=true`. |

> ⚠️ **Microsoft 365 مع username وpassword** (`smtp.office365.com` بـ Basic Auth): Microsoft أعلنت إنها هتقفل الطريقة دي **افتراضياً في أواخر ديسمبر 2026** للـ tenants الموجودة. النظام مش بيدعم OAuth، علشان كده استخدم الـ Connector relay اللي فوق.

الإيميلات بتتبعت في الخلفية، ولو الإرسال فشل بيتعاد مرتين (بعد دقيقة، وبعد 5 دقايق). الطابور ده متخزن في الذاكرة، فلو السيرفر عمل restart والإيميل لسه مستني، بيضيع. بس الإشعار نفسه جوه النظام بيفضل موجود.

## 7) اللغة: عربي / English
- زرار **EN / ع** في الشريط العلوي بيقلب الواجهة كلها بضغطة: الاتجاه (RTL/LTR)، والنصوص، والتواريخ.
- اللغة **بتتحفظ لكل مستخدم على السيرفر**، فتفضل معاه على أي جهاز يدخل منه. وشاشة الدخول فيها نفس الزرار.
- **الإيميلات اللي رايحة للموظفين** بتوصل بلغة الموظف. لو لسه ماختارش لغة، بتوصل بالاتنين.
- **النصوص الجاهزة بتظهر بلغة كل مستخدم:** التصنيفات، والردود الجاهزة، والبيانات التجريبية (التذاكر والأسماء والأصول ومقالات قاعدة المعرفة). يعني نظام اتعمله إعداد بالعربي، أي مستخدم مختار English بيشوف النصوص دي بالإنجليزي، والعكس. الترجمة دي **في العرض بس**: البيانات المحفوظة مابتتغيرش، وأي نص كتبه المستخدم بيفضل زي ما اتكتب. لو عدّلت نص جاهز وحفظته، بيتحفظ باللغة اللي كنت شايفه بيها.
- **البيانات الافتراضية بتتعمل بلغة شاشة الإعداد:** التصنيفات، والردود الجاهزة، والبيانات التجريبية لو اخترتها. يعني لو عملت الإعداد بالإنجليزي، كل حاجة بتطلع إنجليزي من أول يوم. والنسخة الـ Offline بتعمل نفس الشيء على حسب لغتك.
- **الـ Portal** فيه زرار اللغة بتاعه. والإيميلات اللي رايحة لمقدم الطلب بتمشي على اللغة اللي فتح بيها الطلب، ولو التذكرة اتفتحت من جوه النظام بتروح بالاتنين.

## 8) مقدمو الطلبات (Requesters)
مقدم الطلب بقى **سجل محفوظ** بدل ما يكون نص حر. صفحة **مقدمو الطلبات** بتعرض كل شخص ومعاه: عدد تذاكره، والمفتوح منها، وآخر طلب. ولما تضغط على حد بيظهر لك تاريخ طلباته كله.
- **في فورم التذكرة:** اكتب أول حروف من الاسم أو البريد واختار من القايمة، والبريد والقسم بيتملوا لوحدهم. لو الشخص جديد، بيتعمل له سجل تلقائياً، والربط بيتم بالبريد من غير ما يفرق بين حروف كبيرة وصغيرة.
- **التعديل:** أي تعديل على اسم الشخص أو بريده بيتحدث في كل تذاكره.
- **الدمج (أدمن):** لو نفس الشخص متسجل مرتين (مثلاً ببريد شخصي وبريد شغل)، افتحه واختار **"دمج في…"**، وكل التذاكر بتتنقل للسجل الصح.

## 9) بوابة الطلبات (Portal)
صفحة على `http://<السيرفر>:8080/portal` يفتح منها أي موظف في الشركة طلب، **من غير حساب**.
- **التشغيل:** الإعدادات ← بوابة الطلبات ← "تشغيل البوابة". البوابة مقفولة افتراضياً.
- **النطاقات المسموح بيها:** اكتب مثلاً `company.com`، وساعتها محدش يقدر يفتح طلب غير ببريد الشركة.
- **فتح طلب:** الموظف بيكتب بياناته ويختار التصنيف، ويحدد "مين متأثر؟" و"قد إيه مستعجل؟". من الاتنين دول بتتحسب الأولوية بمصفوفة ITIL تلقائياً، وتقدر كمان ترفق صور.
- **رابط متابعة خاص بكل طلب:** فيه token عشوائي طوله 192 bit. من الرابط ده الموظف يشوف حالة الطلب، ويقرا ردود فريق الدعم، ويرد، ويرفق ملفات، ويقيّم الخدمة بعد الحل. الرد على طلب "تم حله" بيعيد فتحه، وعلى طلب "مغلق" ممنوع.
- **"طلباتي" (محتاجة SMTP):** الموظف يدخل ببريده، فيوصله كود من 6 أرقام صالح لمدة 10 دقايق. بعد الدخول يشوف كل طلباته هو بس.
- **إيميلات لمقدم الطلب (لو SMTP مفعّل):** تأكيد الاستلام ومعاه رابط المتابعة، وكل رد من فريق الدعم، وإشعار الحل مع طلب التقييم.

**اللي مقدم الطلب مايشوفوش أبداً:** الملاحظات الداخلية، والمرفقات اللي فريق الدعم رفعها، والمسؤول عن التذكرة، والأولوية، وتفاصيل الـ SLA.

**الحماية:**
- Rate limits: 10 طلبات في الساعة من نفس الـ IP، و5 من نفس البريد، و3 أكواد دخول لكل بريد كل 15 دقيقة.
- كل كود دخول بيتستخدم مرة واحدة، وبيتقفل بعد 5 محاولات غلط.
- حقل مخفي (honeypot) ضد البوتات.
- الـ Portal بيرفض الملفات التشغيلية زي أي مكان تاني في النظام.

> لو هتفتح البوابة للناس من برا الشركة، استخدم Cloudflare (القسم 14). وحط `APP_URL` في `.env` علشان روابط المتابعة اللي في الإيميلات تشتغل.

## 10) ساعات العمل والإجازات (SLA)
الإعدادات ← **ساعات العمل والإجازات**:
- **حساب الـ SLA:** "24/7" (زي الأول)، أو "ساعات العمل بس".
- **المنطقة الزمنية**، و**ساعات كل يوم**. الافتراضي من الأحد للخميس 9 الصبح لـ 5، والجمعة والسبت إجازة.
- **الإجازات الرسمية:** تاريخ واسم، والتاريخ بيتحسب على المنطقة الزمنية المختارة.
- بيظهر لك **مثال مباشر**: "تذكرة P3 مفتوحة دلوقتي هتستحق الحل في…" علشان تتأكد من الإعداد قبل ما تحفظه.

في وضع ساعات العمل:
- وقت الـ SLA بيتعد جوه ساعات العمل بس. يعني تذكرة P1 (4 ساعات) اتفتحت الخميس 4 العصر، بتستحق الأحد 12 الضهر.

## 14) الوصول من برا الشركة (Cloudflare Tunnel)
الطريقة دي بتديك HTTPS تلقائي، ومن غير ما تفتح أي بورت على الراوتر، والبورت الداخلي بيفضل شغال. يعني **لو النت وقع، الفريق جوه الشركة لسه يقدر يشتغل** على `http://<IP-السيرفر>:8080`.

1. من Cloudflare Zero Trust ← Networks ← Tunnels ← Create tunnel، وانسخ الـ **Token**.
2. في الـ Tunnel ← Public hostname:
   - الـ Hostname: مثلاً `helpdesk.company.com`
   - الـ Service: `http://servicedesk:8080`
3. **مهم:** من Access ← Applications ← Self-hosted، على نفس الـ Hostname، اعمل Policy تسمح بإيميلات الشركة بس، بطريقة One-time PIN. ده بيضيف تحقق قبل ما حد يوصل لصفحة الدخول أصلاً.
4. حط الـ Token في `.env`:
   ```
   CF_TUNNEL_TOKEN=eyJh...
   ```
5. شغّل:
   ```bash
   docker compose -f docker-compose.yml -f docker-compose.cloudflare.yml up -d
   ```

**إزاي الإعداد ده متأمّن:**
- السيرفر بيثق في الـ IP الحقيقي (`CF-Connecting-IP`) **من الـ cloudflared container بس**، وده متثبت على IP ثابت `172.30.10.10`. لو حد على الشبكة الداخلية بعت نفس الـ headers، السيرفر بيتجاهلها.
- الـ Cookie بتبقى `Secure` تلقائياً للطلبات اللي جاية HTTPS من الـ Tunnel، وبتفضل عادية للدخول الداخلي بـ HTTP.

> لو الشبكة `172.30.10.0/24` متعارضة مع شبكة عندك، غيّرها هي والـ IPs الاتنين في `docker-compose.cloudflare.yml`.
> بيانات التذاكر بتعدي على Cloudflare مفكوكة التشفير، لأن Cloudflare هو اللي بينهي الـ HTTPS. لو العميل عنده متطلبات compliance تمنع ده، استخدم VPN بدل الطريقة دي.

## 15) الإعدادات (`.env`)
انسخ `.env.example` لـ `.env` وعدّل اللي محتاجه:

| المتغير | الافتراضي | الوظيفة |
|---|---|---|
| `LICENSEE` | (فاضي) | اسم الجهة المرخّص لها. بيظهر في الدخول و"عن النظام" |
| `HOST_PORT` | 8080 | البورت على السيرفر |
| `SESSION_HOURS` | 12 | مدة صلاحية تسجيل الدخول |

| `TRUSTED_PROXIES` | (فاضي) | IPs أو IPv4 CIDR للـ Reverse proxies المسموح لها تبعت `X-Forwarded-*`. فاضي = مفيش ثقة في أي header |
| `REAL_IP_HEADER` | x-forwarded-for | الـ header اللي فيه IP العميل الحقيقي. Cloudflare: `cf-connecting-ip` |
| `SETUP_TOKEN` | (فاضي) | كود إعداد ثابت بدل الكود العشوائي اللي بيطلع في الـ logs |
| `CF_TUNNEL_TOKEN` | — | للـ Cloudflare Tunnel بس |
| `KEEP_BACKUPS` | 14 | عدد النسخ اللي بتتحفظ **لكل نوع** |
| `AUTO_BACKUP_HOURS` | 24 | كل قد إيه تتعمل نسخة تلقائية. `0` = إيقاف |
| `TRASH_DAYS` | 30 | مدة بقاء العنصر في السلة قبل الحذف النهائي. `0` = للأبد |
| `MAX_UPLOAD_MB` | 15 | أقصى حجم للمرفق الواحد (من 1 لـ 100) |
| `APP_URL` | (فاضي) | عنوان النظام، علشان روابط التذاكر في الإيميلات |
| `SMTP_HOST` / `SMTP_PORT` | (فاضي) | سيرفر الإيميل. فاضي = الإيميل مقفول |
| `SMTP_SECURE` | starttls | `starttls` (587/25)، أو `tls` (465)، أو `none` (relay داخلي بس) |
| `SMTP_USER` / `SMTP_PASS` | (فاضي) | فاضي = من غير مصادقة (relay بالـ IP) |

## 17) الأمان
**اللي متطبق في النظام:**
- كلمات المرور متخزنة بـ scrypt (مش نص صريح).
- الـ Sessions في Cookie نوعها HttpOnly + SameSite=Strict، والـ token متخزن hashed في القاعدة.
- حماية CSRF.
- **كود إعداد لمرة واحدة** لشاشة الإعداد الأولى، مكتوب في الـ logs بتاعة السيرفر.
- **قفل لكل حساب** بعد 5 محاولات غلط، بيبدأ 30 ثانية ويزيد تدريجياً لحد 15 دقيقة. غلطات موظف واحد مش بتقفل الشركة كلها حتى لو كلهم طالعين بنفس الـ IP. نفس الحماية على تغيير كلمة المرور.
- **سقف لكل IP:** 30 محاولة غلط كل 15 دقيقة، ضد password spraying.
- الـ headers الجاية من Proxy بيتصدق عليها من الـ IPs اللي في `TRUSTED_PROXIES` بس.
- **CSP صارم:** `script-src 'self'`، يعني مفيش أي JavaScript inline. لو حصل أي XSS، المتصفح هيمنعه من التنفيذ.
- Security headers (X-Frame-Options، nosniff، Referrer-Policy).
- الـ Container شغال non-root، والـ filesystem بتاعه read-only، ومن غير Linux capabilities.

**اللي لازم تاخد بالك منه:**
- **الاتصال الداخلي HTTP عادي (مش مشفر).** ده مقبول على شبكة داخلية موثوقة. لو فيه Wi-Fi ضيوف على نفس الشبكة، افصلهم بـ VLAN.
- **متعرضش البورت 8080 على الإنترنت مباشرة.** للوصول من بره استخدم القسم 14 (Cloudflare) أو VPN.
- لو حطيت Reverse proxy تاني (Caddy أو Nginx)، حط الـ IP بتاعه في `TRUSTED_PROXIES`، وإلا قفل محاولات الدخول هيشوف كل الناس على إنهم IP واحد.

## 20) الأصول والصيانة الوقائية (ITIL / ISO)
من القائمة: **الأصول (CMDB)**. فيها تبويبين: **سجل الأصول** و**خطط الصيانة الوقائية**.

**سجل الأصول:**
- **دورة حياة الجهاز:** في المخزن، قيد الاستخدام، في الصيانة، خارج الخدمة، تم التخلص منه.
- **بيانات كل جهاز:** المالك (موظف من "مقدمي الطلبات" أو قسم)، الموقع، السيريال، المورد، تاريخ الشراء، نهاية الضمان، والأهمية للشغل.
- **صفحة الجهاز** (اضغط على أي صف):
  - كل تذاكره بالترتيب.
  - سجل تلقائي لكل تغيير في الحالة والمالك والمكان: مين غيّر وإمتى.
  - **MTTR** (متوسط وقت إصلاح الأعطال) و**MTBF** (متوسط الوقت بين الأعطال).
  - الصيانة الجاية، وزرار "تذكرة جديدة" مربوطة بالجهاز.
- **السجل ده بيكتبه السيرفر بنفسه**، والمستخدم ما يقدرش يعدّله. وكل تعديل في الأصول بيروح كمان لسجل التدقيق.
- **التخلص من جهاز:** ما يتحفظش من غير طريقة وتاريخ، ومعاهم تأكيد مسح وسائط التخزين ورقم الشهادة. الجهاز اللي مسح بياناته مش متأكَّد بيظهر بعلامة حمرا.
- **مؤشرات أعلى الصفحة:** الضمان المنتهي أو اللي هينتهي خلال 30 يوم، والصيانة المستحقة خلال 7 أيام، وتذاكر الصيانة المفتوحة.

**خطط الصيانة الوقائية (للأدمن):**
- الخطة بتحدد الأجهزة: أجهزة محددة، أو **كل أجهزة نوع معيّن** (أي جهاز جديد من النوع ده بيدخل الخطة تلقائياً).
- وبتحدد كمان: التكرار بالأيام، الميعاد الجاي، تفتح التذكرة قبل الميعاد بكام يوم، النوع، التصنيف، المسؤول، وخطوات التنفيذ.
- **في الميعاد:** السيرفر بيفتح **تذكرة لكل جهاز** لوحده (بيفحص كل 10 دقايق، بتوقيت الشركة). الخطوات بتتنسخ Checklist، والتذكرة بتاخد وسم `preventive`.
- **من غير تكرار:** لو فيه تذكرة مفتوحة من نفس الخطة لنفس الجهاز، مش بيفتح تانية.
- **لو السيرفر كان واقف أسابيع:** بيفتح تذكرة واحدة بس، مش تذكرة عن كل دورة فاتت.
- **الأجهزة اللي بره الخدمة:** المتخلَّص منها وخارج الخدمة وفي المخزن ما بيتفتحلهاش صيانة.
- **"شغّل دلوقتي":** بيفتح التذاكر فوراً. لو الخطة ماكانتش مستحقة، الدورة الجاية بتتحسب من النهارده.
- كل تشغيل بيتسجّل في سجل التدقيق كـ `maintenance.run`.

**التوافق:** خريطة كاملة بتربط المميزات بممارسات ITIL وضوابط ISO/IEC 27001:2022 (A.5.9، A.5.11، A.7.13، A.7.14، A.8.13، A.8.15، A.8.32)، والناقص قبل التغطية الكاملة، في ملف **`COMPLIANCE.md`**.
> شهادة ISO بتتمنح للشركة، مش للبرنامج. النظام بيوفر الأدوات والسجلات اللي بتتقدم كدليل وقت المراجعة.

- **الخطوط:** IBM Plex Sans للإنجليزي، وIBM Plex Sans Arabic للعربي، وIBM Plex Mono للأكواد والأرقام.
- **التباين:** كل ألوان النصوص في الثيمات الأربعة متفحوصة على WCAG AA (4.5:1 أو أكتر).

## 22) Claude والذكاء الاصطناعي (MCP) ومفاتيح API
- **الفكرة:** IT Set Desk فيه **MCP server** جاهز، بيخلّي Claude Desktop أو Claude Code يقرا ويشتغل على التذاكر والأصول والصيانة. مثلاً: "إيه المتأخر؟"، "لخّصلي الوضع"، "افتح تذكرة"، "رد على ITS-1024".
- **التفاصيل:** الأدوات الـ 12، والإعداد، والأمان كلهم في **`mcp/README.md`**.
- **مفاتيح API:** من **الإعدادات ← مفاتيح API**.
  - كل مستخدم يعمل لحد 10 مفاتيح، وكل مفتاح "قراءة فقط" أو "قراءة وتعديل"، وصلاحيته من 30 لـ 365 يوم.
  - المفتاح بيظهر مرة واحدة، والسيرفر بيحفظه كـ SHA-256 بس.
  - المفتاح بيشتغل بنفس صلاحيات صاحبه، وكل استخدام بيتسجل في سجل التدقيق باسمه.
  - الأدمن بيشوف كل المفاتيح ويقدر يلغي أي مفتاح.
- **اللي المفاتيح ممنوعة منه:** إدارة المفاتيح، وكلمات السر، والاستيراد والتصدير، والنسخ الاحتياطية. الحاجات دي محتاجة دخول من المتصفح.
- **المفاتيح من سكربتاتك:** `Authorization: Bearer itsd_…`. مش محتاج هيدر CSRF، لأن مفيش كوكيز.

## الترخيص والملكية
IT Set Desk برنامج مملوك لـ **م. عبدالله عامر**، والعميل بياخد **ترخيص استخدام** حسب الاتفاق. التفاصيل في ملف `LICENSE`.
- **اسم الجهة المرخّص لها:** بيتحط في `LICENSEE` في ملف `.env`، وبيظهر في شاشة الدخول وصفحة "عن النظام". لو مفيش اسم، بيظهر "نسخة تقييم".
- **البصمة:** صفحة **"عن النظام"** (من الشريط الجانبي أو الإعدادات) فيها الإصدار والنسخة والمرخّص له والمطوّر وبيانات التواصل. وشاشة الدخول فيها سطر صغير بالإصدار والمطوّر.
- **البيانات** اللي العميل بيدخلها ملكه هو.
- كل ملف كود في أوله سطر حقوق النشر.

> ملف الترخيص ده صيغة عامة كبداية. قبل ما توقّع عقد مع عميل، خلّي محامي يراجعه.
